## 3. How the deck works (architecture)

- **Stage:** one vertical scroll-snap page. Each slide is `.frame > section.slide`, a 1920×1080 stage scaled with `--s` to fit the viewport. Deep links use `#N`. `?shot=N` renders only slide N, fully built, for screenshots.
- **Navigation:**
  - Arrows, PageUp/PageDown and Space move between slides; clickers send these keys.
  - Wheel, trackpad and the right-edge dots also work.
  - Keyboard moves jump instantly with a 0.32 s fade (`.frame.arrive`).
- **Builds:** any element with `data-build="n"` is revealed in groups.
  - Moving **forward by any means** lands at build 0. Moving **back** shows the slide complete, except on a section marked `data-reset` (slide 4), which always starts at build 0.
  - `next()` reveals the next group, then moves to the next slide. `prev()` steps back.
  - Hidden state: `.pending` (fade up 18px). Shown state: `.built`.
- **Auto builds:** `data-auto="ms"` on a `section` reveals its builds on its own after arrival: first after 600 ms, then every `ms`. A clicker press mid-sequence completes the slide. Used on slide 2 (600 ms).
- **Players (`data-play="name"`):** animated SVG pipes driven by `makeFlow()`.
  - With no `data-build`, a player starts when its slide is on screen and stops/resets when you leave.
  - With `data-build`, it starts when that build is revealed.
- **Actions (`data-action="name"` on an empty `span.cue` with `data-build`):** one-off moments called as `actions[name](cue, on)`, with `on=false` when stepping back. Defined: `widen` (slide 4, Coding widens) and `zoom` (slide 6, zoom out to the full lifecycle).
- **`makeFlow(svg, o)`:** the pipe simulation.
  - Items spawn every `o.spawn` s. Each gate `{x, every, waiting}` releases one item every `every` s, so queues form in front of slow gates. The count in `waiting` shows only items that are actually held up.
  - `o.half(x)` sets the pipe's half-width at x. `o.x0/x1` enables a generated body path. `o.throat()` draws blue outlines on the narrow parts.
  - `seed` is the still frame: one array of x positions per stage, with the last array for items already through every gate.
  - `flow.tween(key, to, ms)` animates a shape parameter (used for the Coding width `o.w`).
  - Reduced motion: the still frame stays.
- **No flash on arrival:** a slide entering the viewport is put into its arrival state (build 0 ahead of the current slide, complete behind it) by `prep()` before it is visible, both from `go()` and from the IntersectionObserver, which also preps a slide when it **leaves** the screen; `prep()` switches transitions off (adds `.preload` to the frame) so the reset is instant. The observer uses `rootMargin:"-2px 0px"` because a snapped neighbour touching the viewport edge otherwise counts as visible and never fires a fresh entry (that caused slide 7 to arrive finished and then drain and rebuild in view when revisited by scrolling). Every slide starts at build 0 on load. Test revisits (go forward, back, forward) by keyboard **and** by scroll.
- **Dialogs:** a `button[data-dialog=ID]` opens `<dialog id=ID>` (placed after `</main>`, outside the scaled stage, sized in viewport units). The keydown handler checks for an open dialog first and closes it on any navigation key. Add more dialogs the same way.
- **Logo:** `img.falcon` has no `src`. The script probes `falcon.svg` once and fills every slot if it exists; otherwise the slots stay hidden.
- **Speaker notes:** in `data-notes` on each section, logged to the console on slide change. Keep them updated when slide behaviour changes.

## 4. Design system (decided with the user; do not re-litigate)

- **Colour roles** (Barclays-aligned; the user requires staying inside the Barclays palette):
  - **Ground:** flat navy `--midnight #0B1C2C` with 5% grain; panels `--panel #12293F`, highlighted panels `--panel-hi #15304A`.
  - **Cyan `--accent #00AEEF`:** emphasised words and key numbers only. It reads well on a projector, about 6.8:1 on the ground.
  - **Active Blue `--active #006DE3`:** fills, bars, rules and pipe outlines only, **never text**. Its contrast as text is only about 3.5:1.
  - **Text:** `--ink #FFF`, `--ink-2 #BCCBDA`, `--ink-3 #8FA3B6`. All pass AA on the ground and on panels.
- **Type:** Figtree 600–800 for titles and big numbers (`--font-display`), Source Sans 3 for everything else (`--font`). Both load from Google Fonts. Inter was dropped (flagged as overused; the user chose Figtree + Source Sans 3).
- **Templates:**
  - **Content slide:** 96 × 8 px Active Blue `.rule`, then a 96 px `h2` at a fixed top position.
  - **Statement slide:** vertically centred.
  - **Cards:** one radius `--r: 16px`, solid panels, used only for side-by-side comparison.
- **Footer:** falcon on the left; on the right, an optional source credit, then the deck title "How AI rewired the business analyst role" (the user asked for the title instead of his name), then the slide number. The cover hides the dots, progress bar and footer.
- **Bans** (impeccable craft floor, already agreed):
  - no uppercase "kicker" label above titles;
  - no coloured `border-left` accent stripes on cards;
  - no gradient text;
  - nothing the audience must read below about 28 px.
